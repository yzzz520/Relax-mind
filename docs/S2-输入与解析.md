## 2. 状态机（`useEmotionFlow.js` 的契约）

```js
// 返回值
{
  stage,        // Ref<'input' | 'analyzing' | 'result' | 'error'>
  inputText,    // Ref<string>
  capsule,      // Ref<Capsule | null>   情绪结果（本批先存着，S3 用）
  keywords,     // Ref<string[]>         解析中要显示的实时关键词
  submit,       // (text: string) => Promise<void>
  reset,        // () => void            回到 input 态
}
```

**流转规则**

| 从 | 事件 | 到 |
|---|---|---|
| input | `submit(text)` 且 text.trim().length ≥ 4 | analyzing |
| input | `submit(text)` 且太短 | input（由组件抛校验提示，状态机不处理） |
| analyzing | 接口成功 | result |
| analyzing | 接口抛错 | error |
| error | 用户点"重试" | input |
| result | `reset()` | input |

**竞态处理（必须做）**

用户可能在解析中连点，或点"重试"后又提交。必须用 `requestId` 丢弃过期响应：

```js
let requestId = 0

async function submit(text) {
  const myId = ++requestId
  stage.value = 'analyzing'
  try {
    const data = await analyzeMood(text)
    if (myId !== requestId) return      // 有更新的请求，丢弃本次结果
    capsule.value = data
    stage.value = 'result'
  } catch (e) {
    if (myId !== requestId) return
    errorMessage.value = e.message
    stage.value = 'error'
  }
}
```

> 不写这段，用户快速点两次会出现"结果闪回输入页"或"旧结果覆盖新结果"。这是新手最常漏的 bug。

## 3. Mock 设计（关键决策）

### 3.1 为什么要把关键词提取单独拆出来

状态二要显示：`正在提取关键词：[面试, 下雨, 疲惫]...`

但这句话要在**第 0–600ms** 就出现，而完整的情绪结果要 **1800–3200ms** 才返回。如果关键词跟着结果一起回来，第一句话就没词可显示。

**所以 `mock.js` 必须提供两个函数**：

```js
// 同步函数，立即返回，用于解析动画的第一句话
export function extractKeywords(text) -> string[]   // 2-3 个词

// 异步函数，模拟整体耗时
export async function analyzeMood(text) -> Capsule  // 1800-3200ms
```

`extractKeywords` 用最简单的词典匹配：

| 输入包含 | 返回词 |
|---|---|
| 累 / 疲 / 困 | 疲惫 |
| 雨 / 湿 / 冷 | 潮湿 |
| 挂 / 失败 / 拒 | 挫败 |
| 面试 / 工作 / offer | 面试 |
| 家 / 想 / 一个人 | 想家 |
| 紧张 / 睡 / 焦虑 | 焦虑 |
| 开心 / 拿下 / 成功 | 喜悦 |

匹配不到就返回 `['情绪', '此刻', '难以名状']`。

### 3.2 四组样本（`analyzeMood` 按关键词选）

| # | 触发词 | 喜悦 | 期待 | 平静 | 温暖 | 悲伤 | 焦虑 | 疲惫 | 孤独 | palette |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 累/雨/挂/失败 | 3 | 18 | 20 | 10 | 78 | 62 | 80 | 55 | `['#7C5CFF', '#FF8FB1']` |
| 2 | offer/拿下/成功/开心 | 88 | 85 | 35 | 70 | 5 | 10 | 15 | 0 | `['#FF9F43', '#FFD166']` |
| 3 | 家/一个人/想 | 10 | 30 | 60 | 25 | 58 | 25 | 40 | 82 | `['#3D5AFE', '#00B8D4']` |
| 4 | 紧张/睡/答辩/焦虑 | 5 | 45 | 10 | 15 | 30 | 88 | 70 | 35 | `['#00E5A0', '#7C5CFF']` |

`emotions` 的 8 个键**必须固定且顺序一致**：喜悦、期待、平静、温暖、悲伤、焦虑、疲惫、孤独。维度顺序固定，见 `EMOTION_DIMENSIONS`。

**失败模拟**：如果当前 URL 带 `?fail=1`，`analyzeMood` 直接抛错 `new Error('解析失败')`。这是给你手动测试 error 分支用的，不要加随机失败（会干扰演示）。

## 4. 状态一：`MoodInputStage.vue`

### 布局

```
            此刻，你的心情是怎样的？          ← 发光标题
        what's your mood right now?        ← 英文小字，12px，30% 透明

     ┌──────────────────────────────────┐
     │                                  │  ← textarea，高度 120px
     │  今天面试被挂了，外面还在下雨       │     最多 4 行，超出滚动
     │                                  │
     │                    0/200    [生成情绪胶囊 →]
     └──────────────────────────────────┘
```

- **必须用 `<textarea>`，不用 `<input>`**（用户会写一整句话，单行输入体验差）
- 容器：玻璃拟态（`--glass-bg` + `backdrop-filter: var(--glass-blur)`），圆角 20px，最大宽度 720px
- 字数计数在左下角，超过 180 字变黄，超过 200 字截断
- 按钮在右下角，**禁用态**（内容 < 4 字）时透明度降到 40%

### 交互

| 行为 | 结果 |
|---|---|
| 进入页面 | textarea 自动聚焦 |
| `Enter` | **换行**（不是提交） |
| `Ctrl + Enter` / `Cmd + Enter` | 提交 |
| 点击按钮 | 提交 |
| 内容 < 4 字点提交 | 卡片左右抖动 300ms + 下方提示"再多说一点" |
| 提交后 | 按钮文字变"正在解析情绪波长..."，禁用 |

**抖动关键帧**：

```css
@keyframes shake {
  0%, 100% { transform: translateX(0); }
  20% { transform: translateX(-8px); }
  40% { transform: translateX(8px); }
  60% { transform: translateX(-6px); }
  80% { transform: translateX(6px); }
}
```

## 5. 状态二：`AnalyzingStage.vue`

### 视觉

- 全屏遮罩：`position: fixed; inset: 0; background: rgba(11, 10, 20, 0.78); backdrop-filter: blur(10px);`
- 遮罩之上，垂直居中显示一行文案（20–24px，`--text-primary`）
- 每次切换文案用 **淡入 200ms → 停留 200ms → 淡出 200ms**

### 三条文案（总时长 1800ms）

| 序号 | 时间窗 | 内容 |
|---|---|---|
| 1 | 0–600ms | `正在提取关键词：[{{ keywords.join(', ') }}]...` |
| 2 | 600–1200ms | `情感向量计算中...` |
| 3 | 1200–1800ms | `正在为你寻找专属旋律...` |

### 必须处理的一个时间差

第 3 条在 **1800ms** 结束，但接口可能到 **3200ms** 才返回。中间会有 1.4 秒空白，用户会以为卡死了。

**解法**：第 3 条结束后**不淡出**，保持在屏幕上，并给它加一个呼吸动画（`opacity: 0.5 ↔ 1`，周期 1200ms），直到接口返回。

## 6. 背景：`AuroraBackground.vue`

### Props

```js
defineProps({
  intensity: { type: Number, default: 0.3 },  // 0-1，控制粒子速度与亮度
})
```

### 两成两层

1. **光斑层**（DOM，不用 canvas）：两个 `div`，径向渐变，`filter: blur(80px)`，缓慢椭圆轨迹移动（`animation: 40s infinite alternate`）
2. **粒子层**（canvas）：60–100 个 1–2px 的点，随机初速度，越界环绕

### 必须处理

| 项 | 要求 |
|---|---|
| 高分屏 | canvas 宽高 = `clientWidth * devicePixelRatio`，`ctx.scale(dpr, dpr)` |
| 窗口缩放 | `ResizeObserver` 重建尺寸，不要只监听 `window.resize` |
| 页面切到后台 | `visibilitychange` 时暂停 `requestAnimationFrame`，切回来恢复（省电） |
| 减少动效 | `window.matchMedia('(prefers-reduced-motion: reduce)')` 命中时粒子静止 |
| 性能 | 单帧粒子数 ≤ 100，不要用 `shadowBlur`（很慢） |

### intensity 联动（这是"粒子加速"的实现）

在 `CapsuleView` 里按状态传值：

```vue
<AuroraBackground :intensity="stage === 'analyzing' ? 1 : stage === 'result' ? 0.6 : 0.3" />
```

粒子速度 = `基础速度 * (0.5 + intensity)`，透明度同理。**intensity 变化要平滑过渡**（在 rAF 里用 `lerp` 逼近目标值），突变会显得很生硬。

`stage` 过渡：`opacity 0→1` + `translateY(8px)→0`，320ms。

保留原有的 header 与退出按钮，不要删。
