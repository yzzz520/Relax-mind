## 5. `AudioVisualizer.vue`

### 视觉

- 画布尺寸：桌面 260×260（`devicePixelRatio` 适配），移动端 160×160
- **中心圆**：半径 `36 + 低频能量 * 22`，填充径向渐变 `palette[0] → palette[1]`，外发光用 `ctx.shadowBlur`（只在圆上使用，别给所有元素用）
- **频谱条**：48 根，从半径 62 向外发散，长度 `4 + 频段能量 * 40`
- 未播放时：中心圆按 `sin(t)` 缓慢呼吸，频谱条停在最短长度（4px），透明度 30%

### 两套实现（自动选择）

```js
// 有音频且 AnalyserNode 可用 → 真实频谱
if (analyser) {
  analyser.getByteFrequencyData(dataArray)
  // dataArray[i] / 255 → 0..1 的能量
} else {
  // 降级：正弦呼吸
  level = 0.5 + 0.5 * Math.sin(now / 900)
}
```

### 必须避开的 5 个坑（这一批的主要风险）

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | `AudioContext` 在用户手势前创建 | Chrome 报 `suspended`，没声音 | **在第一次点击播放时才创建** `new AudioContext()` |
| 2 | 同一个 `<audio>` 元素重复 `createMediaElementSource` | 抛 `InvalidStateError`，播放器彻底哑掉 | source **只创建一次**，存在 ref 里；组件卸载时 `disconnect()` 并置空 |
| 3 | 卸载时不 `disconnect` / `close` | 音频节点泄漏，切页面多了会卡 | `onBeforeUnmount` 里 `source.disconnect()`、`analyser.disconnect()` |
| 4 | `requestAnimationFrame` 在卸载后继续跑 | 报错 "Cannot read properties of null" | 保存 `rafId`，卸载时 `cancelAnimationFrame` |
| 5 | 用 `setInterval` 驱动动画 | 掉帧、和音频不同步 | 必须用 `requestAnimationFrame` |

### 关键代码骨架（照此实现）

```js
// useAudioAnalyser.js
let ctx = null          // 模块级单例，全局只用一个 AudioContext

export function getContext() {
  if (!ctx) ctx = new (window.AudioContext || window.webkitAudioContext)()
  return ctx
}

export function createAnalyser(audioEl) {
  const context = getContext()
  const source = context.createMediaElementSource(audioEl)   // 每个元素只能调一次
  const analyser = context.createAnalyser()
  analyser.fftSize = 128                                     // → 64 个频段
  source.connect(analyser)
  analyser.connect(context.destination)                      // 必须接，否则没声音
  return { source, analyser, context }
}
```

## 6. 疗愈语打字机效果

`HealingComment.vue` 增加逐字显示：

- 每字 28ms，标点后额外停 120ms
- 显示期间光标闪烁（`▌`，`animation: blink 1s step-end infinite`）
- 完成后光标消失
- `prefers-reduced-motion` 命中时**直接全部显示**
- 组件卸载时清除定时器

> 注意：不要用 `setInterval` 累加字符串后 `innerHTML`，直接用 `ref` + 模板插值。
