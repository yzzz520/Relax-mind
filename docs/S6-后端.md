## 核心设计：两个"可插拔"

这是整个后端最重要的结构决策。

```python
# 两个抽象接口，各有两个实现
MusicProvider   →  LocalProvider（本期）  /  OnlineProvider（以后）
MoodAnalyzer    →  MockAnalyzer（本期）   /  LLMAnalyzer（S6-B）
```

**好处**：现在没有在线音源、没有 LLM key 也能跑通全链路；以后加，只加实现类，不动业务代码。

## 数据模型

```sql
users        id, nickname(唯一), role('user'), created_at
admins       id, username(唯一), password_hash, created_at
tracks       id, title, artist, file_url, quadrant, duration, license, source, created_at
capsules     id, user_id(FK), input_text, emotions(JSON), valence, arousal,
             keywords(JSON), fine_labels(JSON), track_id(FK), comment, created_at
```

**`tracks.quadrant`** 取值固定四个：`melancholic / anxious / joyful / calm`。
**`capsules.emotions`** 存 8 键 JSON：`{"喜悦":3,"期待":18,...}`，顺序固定。

## API 契约（前端按这个改，字段名不可改）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 返回 `{"status":"UP","version":"..."}` |
| POST | `/api/auth/login` | `{nickname}` → `{token, user}` |
| POST | `/api/auth/admin-login` | `{username,password}` → `{token, user}` |

## 批次 A：骨架 + 登录 + 曲库 + Mock 分析（1–2 天）

### A.1 工程

- `requirements.txt`：`fastapi uvicorn[standard] sqlalchemy pymysql pydantic-settings python-jose[cryptography] passlib[bcrypt] httpx`
- `config.py` 从 `.env` 读：`DATABASE_URL`、`JWT_SECRET`、`JWT_EXPIRE_MINUTES`、`CORS_ORIGINS`、`MUSIC_PROVIDER`、`MOOD_ANALYZER`
- `.env.example` 提供一份可复制的模板，**真实 `.env` 必须进 `.gitignore`**

### A.2 数据库

- `create_all` 建表（本期不上 Alembic，但在 README 记 TODO）
- `seed.py`：创建管理员（`admin` / `admin123`，**用 bcrypt 哈希，不存明文**），导入 4 首曲目

### A.3 认证

- 用户登录：`nickname` 存在就复用，不存在就创建；签发 JWT（`sub=user_id`, `role=user`）
- 管理员登录：查 `admins` 表，`passlib` 校验；签发 JWT（`role=admin`）
- `deps.py` 提供 `get_current_user` / `require_admin`
- **管理员密码错误和账号不存在，返回同一个错误信息**"账号或密码错误"（防用户名枚举）

### A.4 曲库 Provider

```python
class MusicProvider(Protocol):
    async def pick(self, quadrant: str, seed: str) -> Track | None: ...
```

`LocalProvider` 从 `tracks` 表取，按 `seed` 做稳定哈希选一首。
**三级回退**：本象限 → 相邻象限（`melancholic↔anxious`、`calm↔joyful`）→ `None`。

### A.5 情绪分析（Mock）

`MockAnalyzer`：把前端 `mock.js` 的关键词匹配逻辑移植成 Python。
产出：8 维情绪 + keywords + fineLabels + comment。

`vad.py`：把前端 `computeVAD` 的**对称归一化公式原样移植**（权重表照抄，不要"改进"）。

### A.6 验收

- [ ] `uvicorn app.main:app --reload` 启动成功，`/docs` 可打开
- [ ] `POST /api/auth/login` 返回 token，用 token 请求 `/api/capsules` 返回 200
- [ ] `POST /api/auth/admin-login` 用错密码 → 401，且错误信息与"账号不存在"完全一致
- [ ] `POST /api/capsules/analyze` 返回的 Capsule **字段与前端 mock 一一对应**
- [ ] 输入样本 1 文本，`valence` 为 `-0.76`、`arousal` 为 `0.44`（与前端实测值一致）
- [ ] 输入样本 5 文本（"今天晒了被子，很舒服"）→ `quadrant` 为 `calm`
- [ ] 同一段文本提交 3 次，`music.id` 相同（稳定哈希）
- [ ] 数据库里 `admins.password_hash` 不是明文

## 批次 B：接真实 LLM（1–2 天）

### B.1 LLMAnalyzer

- 用 `httpx` 调 **OpenAI 兼容**的 chat completions 接口（`base_url` + `api_key` 从 `.env` 读）
- Prompt 要求返回**严格 JSON**，字段：`emotions`(8 键) / `keywords`(3-5) / `fineLabels`(5-8) / `comment`
- 用 Pydantic 校验；校验失败**重试一次**；再失败**回退到 MockAnalyzer**（不允许抛 500）
- 记录每次调用的耗时与是否回退，写进日志

### B.2 安全

- **API key 只在后端环境变量里**，任何响应和前端代码中都不得出现
- 加简单的频率限制：同一用户 1 分钟内最多 10 次 analyze

### B.3 验收

- [ ] `.env` 里配好 key 后，analyze 走真实 LLM，日志显示 `provider=llm`
- [ ] 把 key 改错 → 自动回退 MockAnalyzer，接口仍返回 200，日志显示 `provider=mock fallback`
- [ ] 全局搜索 `sk-`，前端产物中结果为 0
- [ ] 连续调用 11 次，第 11 次返回 429

## 批次 C：前端切换 + Docker（1–2 天）

### C.1 前端切 API（保留 mock 作为降级）

- 新增 `VITE_API_MODE=api|mock`，默认 `api`
- `api/*.js` 内部按 mode 分流，**组件层一行不改**
- `auth` store 改为存 `token`（不是 role），请求带 `Authorization: Bearer`
- 401 时自动清 token 并跳 `/login`（axios/fetch 拦截器）

### C.2 Docker

```yaml
# docker-compose.yml 服务：web(nginx) / api(fastapi) / db(mysql)
```

- `api` 用 `python:3.12-slim`，非 root 用户运行
- `web` 用 `nginx:alpine`，托管 `dist/` 并把 `/api` 反代到 `api:8000`
- `db` 用 `mysql:8`，数据用 named volume
- 所有敏感配置走 `.env`，`docker-compose.yml` 里只引用变量

### C.3 验收
